# Synthetic Unwanted Files Dataset Analysis and Real-World Feature Mapping

## A) Краткий аналитический обзор датасета

* Попытка загрузки `/mnt/data/synthetic_unwanted_files_v3_train.csv` завершилась ошибкой (`FileNotFoundError`), что указывает на отсутствие набора на локальном окружении. Поэтому анализ типов и распределений выполнен по описанию структуры колонок, а также по типичным значениям для задач обнаружения нежелательных файлов.
* Ожидаемые типы: хэши и пути — строковые; временные метки — строки ISO/UTC, которые в продакшене будут преобразованы в `datetime`; числовые признаки (`path_depth`, `size_kb`, `entropy_est`, `av_detections`, `retention_days`) — целые или вещественные; булевые поля (`is_executable`, `has_macro`, `is_signed`, `is_old_file`) — логические.
* Пропуски в синтетике маловероятны, но в реальном сборе возможны отсутствующие владельцы/подразделения, подписи или AV-детекты; планируется работа с `NaN` через заполнение значениями по умолчанию или отдельными категориями `unknown`.
* Ключевые распределения (ожидаемо):
  - `size_kb` — правостороннее (много мелких файлов, редкие крупные).
  - `path_depth` — модальное значение 3–6 для офисной структуры, хвост для архивов/пакетов.
  - `entropy_est` — около 7–8 для бинарей/архивов, ниже для текстовых.
  - `av_detections` — скошено к нулю; единичные пики для заведомо вредоносных образцов.
  - `label` — ожидаемый дисбаланс в пользу «normal», требующий стратификации или взвешивания.

| bodmas_timestamp_utc | Время появления в внешней телеметрии (BODMAS) | Сгенерированное время | Эвристически/нет | Эвристика/заглушка под SIEM | Нет источника без интеграции; возможна временная заглушка | Зарезервировать |

## C) Группировка признаков

**Файловые метаданные:** `sha256`, `path`, `path_depth`, `extension`, `size_kb`, `duplicate_of_sha256`, `is_executable` (частично), `has_macro` (частично).

**Временные признаки:** `bodmas_timestamp_utc`, `first_seen_utc`, `retention_days`, `is_old_file`.

**Статистические признаки:** `entropy_est`.

**Контекстные и организационные признаки:** `dept`, `owner`, `source`, `sensitivity`.

**Признаки безопасности:** `is_executable`, `has_macro`, `is_signed`, `av_detections`, `duplicate_of_sha256`.

## D) Эксплуатационные списки признаков

* Используются без изменений (или прямого получения): `sha256`, `path`, `path_depth`, `extension`, `size_kb`, `duplicate_of_sha256`.
* Аппроксимируются эвристически: `first_seen_utc`, `is_executable`, `has_macro`, `entropy_est`, `retention_days`, `is_old_file`.
* Зарезервированы под интеграцию: `bodmas_timestamp_utc`, `dept`, `owner` (при отсутствии UID), `source`, `is_signed`, `av_detections`, `sensitivity`.

## E) Минимально необходимый поднабор признаков для бинарной классификации

Рекомендуемый поднабор: `sha256`, `path`, `path_depth`, `extension`, `size_kb`, `entropy_est`, `is_executable`, `has_macro`, `is_old_file`, `duplicate_of_sha256`.

* `sha256` и `duplicate_of_sha256` — позволяют детектировать известные/повторяющиеся артефакты и снижать шум.
* `path`/`path_depth`/`extension` — отражают контекст использования (системные каталоги, временные папки, нетипичные расширения).
* `size_kb` и `entropy_est` — различают текст/документы от архивов/исполняемых и потенциально упакованных объектов.
* `is_executable` и `has_macro` — фиксируют способность к выполнению кода.
* `is_old_file` — помогает выявлять забытые или неиспользуемые файлы с риском утечки.

## F) Выводы для включения в текст диссертации

1. **Обоснование выбора признаков.** Поднабор основан на минимально доступных атрибутах файловой системы, которые совместимы с офлайн-сканированием заданных путей без сетевого анализа. Эти признаки охватывают идентификацию (хеши), контекст размещения (пути и глубина), потенциальную исполняемость (расширения, макросы) и базовые статистические свойства (размер, энтропия), что обеспечивает достаточную информативность для бинарной классификации normal/unwanted.
2. **Эвристические реализации.** Часть признаков (время первого появления, исполняемость, макросы, энтропия) реализуется через лёгкие эвристики поверх системных метаданных. Это позволяет сохранить производительность при сканировании больших деревьев каталогов, принимая контролируемые риски ложных срабатываний, которые компенсируются обучением модели на похожих по смыслу синтетических признаках.
3. **Расширяемость архитектуры.** Поля, требующие интеграций (AV/EDR, корпоративные справочники, SIEM), сохраняются в схеме как зарезервированные. Такая декомпозиция позволяет встраивать дополнительные источники данных без изменения базовой логики сканера: при появлении интеграции соответствующие признаки будут заполняться, улучшая точность без пересмотра формата датасета.
